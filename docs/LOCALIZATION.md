# Поддержка переводов интерфейса

Каталог: `src/GaameTranslate.Core/UiStrings.json`. У каждого ключа есть значения `ru` и `en`. Ключи соответствуют исходным подписям; при изменении исходной формулировки обновите её использование и запись в каталоге. Названия брендов и нейтральные обозначения могут совпадать в двух языках. Не меняйте идентификаторы провайдеров, коды языков, сочетания клавиш, API-поля и значения команд.

В XAML используйте `{loc:Loc Key='Подпись'}`. Для параметров: `{loc:Loc Key='Сохранено: {0}', Value={Binding WordCount}}`. Для вычисляемого сообщения: `{loc:Loc Key={Binding Status}}`. Если ключ начинается с фигурной скобки, добавьте стандартный префикс экранирования `{}`. Пустое значение пользовательского поля можно обработать через `Fallback`, не переводя непустое содержимое.

В C# используйте `Ui.SetText`, `Ui.SetContent`, `Ui.Localize` и `UiText.M`. `UiMessage` хранит ключ и аргументы до отображения. Передавайте даты и числа как аргументы, а не форматируйте их заранее. `UiText.Join` позволяет составлять список переводимых строк без фиксации языка. Исключения `UserFacingException` также принимают `UiMessage`; при показе сохраняйте `LocalizedMessage`, например через `Ui.Error`.

Пользовательский текст выводите обычной привязкой или как аргумент нейтрального шаблона `UiText.M("{0}", text)`. Не используйте содержимое карточек, результатов OCR, перевода или словарных статей как ключи интерфейса. Для динамических списков `LanguageChoice.DisplayName` поддерживает сообщение с аргументами, а общий шаблон отображает его на текущем языке.

Проверки: `LocalizationTests` проверяет оба значения и совпадение аргументов. `dotnet run --project tests/GaameTranslate.Windows.Verify -c Release --no-build -- artifacts/localization --localization` проверяет смену языка в уже открытых окнах и аудит ресурсов посещённых привязок. Добавляйте в этот сценарий новые окна и состояния. Внешние сообщения сервисов и системные окна Windows не принадлежат каталогу приложения.
